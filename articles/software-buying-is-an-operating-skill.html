Software buying is an operating skill

The stack is no longer an IT catalog. It is how the company actually runs — and most firms still buy it like office supplies.

Edited by Emilio Santos August 31, 2026 8 min read Updated October 24, 2026

Walk a mid-market close, a warehouse, or a support queue and you are walking a software path. Invoice to cash lives in one product. Exceptions live in a spreadsheet someone swore they would retire. Escalations live in a chat tool that is not the “system of record.” Buying those tools as if they were toner is how you get seven CRMs and one actual process.

The companies that waste the least money do not have a prettier vendor matrix. They have a named owner for each workflow, a kill date for overlapping seats, and a rule that a new logo cannot enter without a retirement plan for an old one.

Stop scoring demos

Demos are designed to make the happy path look inevitable. Score the unhappy path: month-end, chargebacks, a warehouse that is offline, a customer who is not in the dropdown. If the product cannot show that without a services SOW, you are not buying software. You are buying a project.

A seat that nobody can turn off is not a subscription. It is a tax.

The three questions that belong in procurement

What work dies if this tool is down for a day? Who is allowed to add a seat? What is the exit — export, escrow, or a second vendor already on the bench? If finance cannot answer those, IT will answer them during an outage, which is the expensive way.

Make renewal a product review

Annual renewals are where vendors hide price. Treat them like a product review: usage, overlapping tools, and whether the original problem still exists. A 8% increase on a tool that replaced two others can be cheap. A 0% increase on a tool nobody opens is still a loss.

Software buying is now an operating skill because the company is the stack. Hire for that, or keep paying for catalogs.

The scorecard is the software renewal scorecard. Operator guides: Software buying as an operating skill and How to read a SaaS renewal. If the renewal now includes an agent, the sheet is the agent access limit sheet, then Limit what an agent can touch.

Updated October 2026: why this is a bigger deal now

This note first ran on August 31 as a short operator essay. Since then, two things have made the buying decision heavier. First, more renewals now include AI features or agents that can act inside the product, which changes what you are approving. Our agent access guide covers that. Second, public guidance on what to ask a software vendor has grown. CISA’s 2026 minimum elements for a software bill of materials, covered in SBOM now covers the suite, give buyers a named list to put in a contract.

Why it matters, by role

CFO. Software is a recurring cost that grows quietly. Seats get added and rarely removed. Price increases arrive at renewal, when switching is hardest. The finance lever is timing: decisions made 90 days before renewal are cheaper than decisions made in the last week. How to read a SaaS renewal lays out the 90, 60, and 30-day steps.

CISO. Every new tool is a new place for data, a new identity to manage, and a new vendor to monitor. CISA’s Secure by Demand guide, published with the FBI in August 2024, lists questions buyers can ask before purchase: whether the vendor offers single sign-on and logging in the base product, whether it publishes a vulnerability disclosure policy, and whether it can provide an SBOM. Ask those before the contract, not after the incident.

Founder. Early-stage companies tend to buy tools one at a time, each for a good reason. Two years later, three tools do the same job and nobody can turn any of them off. Name an owner for each workflow early. It costs nothing and saves a cleanup project later.

Operator. You live with the tool after the contract is signed. Ask to see the unhappy path in the demo: month-end, a failed sync, an offline site, an exception that does not fit the dropdown. If the vendor cannot show it, plan for the workaround.

A buying checklist that fits on one page

  1. Name the workflow and the owner. One person, by name, who can say what the tool is for and when it would be retired.
  2. List what it replaces. If nothing is retired, the new tool is additive cost. Write the retirement date for any overlapping tool.
  3. Score the unhappy path. Pick three hard cases from your real operations and ask the vendor to run them.
  4. Ask the security questions. SSO and MFA in the base tier, security logs you can export, a public vulnerability disclosure policy, and an SBOM on request. These come from CISA’s Secure by Demand guide.
  5. Set the seat rule. Who can add seats, and who reviews unused seats each quarter.
  6. Write the exit. Full data export in a documented format, a data-return window after the contract ends, and a notice period you can meet.
  7. Cap the price. A contractual cap on renewal increases. A blank increase clause is the vendor’s option, not yours.

A worked example

The numbers below are illustrative, not survey data. Say a team pays for 120 seats of a tool at $400 per seat per year, or $48,000. In the last 30 days, 66 people logged in. That is 55% use. Before renewal, the owner proposes cutting to 75 seats to leave room for growth. At the same per-seat price, the new cost is $30,000, a $18,000 saving, before any price negotiation. If the vendor also proposes an 8% increase, the right comparison is the new price on 75 seats, not the old price on 120.

Run those inputs through the software renewal scorecard and it flags the seat gap and any missing price cap, and writes the requests for the vendor email.

What to watch next

  • AI features inside renewals. Watch for new clauses on training, data use, and agent actions added to existing products. They change the risk of a tool you already own.
  • EU cloud switching. For EU data processing services, the Data Act ends switching charges on January 12, 2027. Check whether your vendors update exit terms. The detail is in the cloud repatriation note.
  • Vendor security artifacts. More buyers are asking for SBOMs and security logs in the contract. If your vendor cannot provide them, that is information about the vendor.
