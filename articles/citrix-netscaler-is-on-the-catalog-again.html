Citrix NetScaler is on the exploited catalog again

CISA added CVE-2026-88779 on October 4. The catalog due date is October 7, the day of this briefing. The September NetScaler rows are a different pair of bugs.

By Emilio Santos October 7, 2026 16 min read

On Sunday, October 4, 2026, the Cybersecurity and Infrastructure Security Agency published a short alert: one vulnerability had been added to the Known Exploited Vulnerabilities catalog, based on evidence of active exploitation. The name on the alert is CVE-2026-88779, Citrix NetScaler, an improper restriction of operations within the bounds of a memory buffer. The alert does not print a due date. The catalog does. The row was added October 4. The due date is October 7. Known ransomware campaign use is Unknown. Forensic triage is marked Yes. The catalog file that carries those fields, version 2026.10.04, was released the same Sunday. On Monday, October 5, CISA Cyber posted the CVE on X: the agency had added Citrix NetScaler vulnerability CVE-2026-88779, that same memory-buffer weakness, to the catalog, and told readers to apply mitigations.

This briefing is dated October 7, 2026, the same calendar day as the due date on the row. For a Federal Civilian Executive Branch agency, that clock is today. It is the date on the entry. It is not a date that has already slipped, and it is not a date that arrives tomorrow. For a company the directive does not name, the row is still the official statement that CISA has evidence the bug is being used.

This is an operator note, not a description of how to use the bug. If you run NetScaler ADC or NetScaler Gateway, including under the older names Citrix ADC and Citrix Gateway, the job is to confirm that, open the vendor page the catalog names, apply the fix that page describes, and write down the date. If you do not run it, write that down too, so the next person does not reopen the thread because a contract still says Citrix.

What the row actually says

CISA’s short description is specific, and it is narrower than the vulnerability name suggests. Citrix NetScaler ADC (formerly Citrix ADC) and Citrix NetScaler Gateway (formerly Citrix Gateway) contain an improper restriction of operations within the bounds of a memory buffer that could allow for a denial of service. The product field is NetScaler. The vendor field is Citrix. The weakness identifier on the row is CWE-119. That is the whole impact line. Denial of service means the box can be taken down. It is not, on this row, a claim of remote code execution, and it is not a claim that an outsider can run commands.

The required action is the catalog instruction on the row. Apply mitigations in accordance with vendor instructions, in line with Binding Operational Directive 26-04 and with CISA’s Forensics Triage Requirements. Follow the directive’s guidance for cloud services, or stop using the product if no mitigation exists. Forensic triage on this row is Yes. That Yes is an agency instruction. It is also the reason a private company should not file the printout under “patch only” without someone asking whether the logs deserve a look.

The notes field is the remediation list. It names two Citrix pages: support article CTX697174, and a Citrix community post titled as an explanation of how to understand and address CVE-2026-88779 in NetScaler ADC and NetScaler Gateway. It then names BOD 26-04, the forensics triage guidance published with that directive, and the National Vulnerability Database entry for the CVE. Those are the pages. This briefing does not reprint build numbers from them. A version string copied into a chat is how a team patches the wrong train and calls the row closed. Open CTX697174, read the affected releases there, and write the build you are on next to the build Citrix says is fixed.

The October 4 alert uses a sentence CISA attaches to this class of bug: this type of vulnerability is a frequent attack vector and poses significant risk to the federal enterprise. That sentence describes the type. It is not a count of how often this CVE has been used, and it is not a finding that this particular bug hands over the whole appliance. Read it as the alert’s boilerplate. Read the catalog description when someone asks what this entry can do.

The alert tells you the name. The catalog tells you the date. The vendor page tells you the fix. Skip one of the three and you are guessing.

Who the date binds

The October 4 alert cites BOD 26-04, Prioritizing Security Updates Based on Risk, as the directive that sets vulnerability-management requirements for Federal Civilian Executive Branch agencies. The alert says the directive applies only to those agencies, and that CISA encourages every other organization to put catalog vulnerabilities first. BOD 22-01 is the older directive that required those same civilian agencies to remediate a listed vulnerability by the due date on the entry. CISA’s program page still says that older directive does not bind everyone else. This row’s required action and its notes point at BOD 26-04 and at the forensics guidance. That is the document to open if a federal customer asks which rule you followed.

The alert also describes how BOD 26-04 sorts work. Agencies are told to move fastest on catalog entries that, on a publicly exposed asset, grant total control after exploitation, and to defer lower-risk vulnerabilities. That is the directive’s sorting rule. It is not CISA’s description of CVE-2026-88779. The description on this row is denial of service. Do not brief a board that this entry is a total takeover because the alert mentioned total control in that sorting rule. A remote-access gateway that stops answering is still an outage: a failed login for every customer on it, and a long night for whoever still knows the old hostname.

A due date with an agency’s name on it is a federal clock. The same row is still evidence that someone is already using the bug against organizations that have no federal clock at all. Ransomware use is marked Unknown. Unknown is not a clean bill. It means CISA has not published that link. Do not brief a board that “this is not ransomware” off that field.

Forensic triage marked Yes is the catalog’s way of saying agencies under BOD 26-04 have to check whether the system was compromised before the patch, using the forensics guidance linked in the notes. This briefing does not restate that guidance, and it does not list log paths or commands. A private company can still decide, with its own counsel and its own logs, whether a bug CISA has called exploited deserves a look backward as well as a patch forward. That decision is not this article.

This is not the September NetScaler pair

The catalog already had this product family on it. On September 27 CISA added CVE-2026-88771 and CVE-2026-88772, both due September 30. Those federal dates have passed. The write-up of that week is CISA listed three bugs attackers are already using. The September rows are still the rows. This October entry does not replace them, and closing them does not close this one.

The first September bug, CVE-2026-88771, is improper input validation. CISA says it could let an unauthenticated attacker run arbitrary commands on NetScaler ADC and NetScaler Gateway. The second, CVE-2026-88772, carries almost the same vulnerability name as the October row: an improper restriction of operations within the bounds of a memory buffer. The short description is different. CISA says the September memory bug could allow remote code execution or a denial of service. The October memory bug, CVE-2026-88779, is described only as a denial of service. Same product. Similar title. Different CVE, different impact line, different due date, different notes.

The September notes point at a different Citrix bulletin, CTX697096, and at Citrix’s write-up of CVE-2026-88771 through CVE-2026-88778. They also say that running the indicators Citrix provided in the NetScaler console may help identify exploitation, and that customers must do the forensic triage BOD 26-04 directs. That is the September instruction. It is not a procedure this page is going to walk, and it is not the notes field on CVE-2026-88779. The October notes name CTX697174 and the later community post. A build that satisfied the September 30 rows is not, by that fact alone, the build this row requires. If the change window in late September was treated as “NetScaler is done,” reopen it and read the new page.

Names are how this gets missed. CISA’s October description uses both the current names and the former ones, Citrix ADC and Citrix Gateway, in the same sentence. A contract, a diagram, or an invoice may still say Citrix. Ask which box you run, which box a partner runs, and which box a Citrix-operated service already moved. The required action’s cloud line is there because those are often not the same appliance.

What to write down today

Make one line, not a program. Product: NetScaler ADC and NetScaler Gateway, and the former names, because that is how the catalog writes them. Next to it: yes, no, or owned by the host. For every yes, write the build you are on, the build CTX697174 says is fixed, the person who can change it, and the date you will check again. If the answer is owned by the host, write the name of the host and the date you asked. For a federal contractor, also write October 7. A customer may ask why the catalog date was missed even when BOD 22-01 and BOD 26-04 do not name you.

Do not turn the line into a claim that you were or were not compromised. The catalog’s Yes on forensic triage tells agencies to look, under the guidance CISA linked. It does not tell a private company what its logs will show. Unknown on ransomware stays Unknown until CISA changes the field.

If the same week produces a question from a public company, the patch date and the materiality date are different clocks. Item 1.05 of Form 8-K runs from the materiality determination, not from the morning a CVE is added to the catalog. A known-exploited bug is not automatically a material incident. It is a fact your customer’s counsel may ask you to explain quickly: what you run, what you patched, and when you decided the incident was or was not material. The note on that clock is the SEC piece. The checklist beside it is Before the Form 8-K clock.

If the box is in the rack, the page to finish is CTX697174. If the box is not yours, the sentence to send is the one that says so, with the date on it. The monthly window can still exist. This row does not wait for it.
