N-able took N-central offline. Ask your MSP if they use it.

A researcher published 33 unpatched flaws, with exploit code, in the tool many managed service providers use to run client computers. N-able took hosted N-central down, told on-premises customers to leave servers off, and released its hotfix on the afternoon of November 10.

Edited by Emilio Santos November 10, 2026 4 min read

Update, November 10, 2026, 4:10 PM ET: N-able has released the hotfix. Its N-central 2026.4 HF2 release notes, posted at 3:48 PM ET, describe Hotfix 2 (build 2026.4.1.26) as a critical security update and list seven CVEs it fixes. On-premises customers should upgrade the server to 2026.4.1.26 before bringing it back online. N-able upgrades hosted servers itself. Everyone, hosted and on-premises, must also upgrade Agents and Probes, Agents first and then Probes, or Agents can lose contact with an upgraded Probe. N-central’s built-in remote control is temporarily disabled in this build; Take Control still works. As of 4:05 PM ET, N-able’s status incident had not yet been updated to confirm general availability, and N-able still reports no evidence that any customer environment was successfully exploited.

On Monday, November 9, 2026, N-able took its hosted N-central service offline in the Americas, Europe and Asia-Pacific. It also told customers who run N-central on their own servers to shut those servers down and leave them off until N-able says they can come back. The move followed a researcher’s public release of 33 unpatched flaws, with working exploit code, in the remote monitoring tool many managed service providers use to run their clients’ computers.

If an IT provider manages your office computers, ask them today whether they use N-able N-central.

What happened

Late Sunday, November 8, security researcher Sean Bales published a set of flaws he called Able2Shell, including proof-of-concept exploits, according to BleepingComputer. Huntress, which reviewed the research, counts 33 flaws that can be chained into four attacks: three that can run code on the N-central server and one that can raise privileges to root. The researcher tested them against N-central Appliance 2026.4.0.31 and said earlier versions are likely affected.

N-able then announced a critical security incident. In a statement to BleepingComputer it said it took hosted N-central offline on November 9 as a precaution and told on-premises customers to take their servers offline until further notice. At that time it said it had not observed active exploitation.

As of mid-morning November 10, Eastern time, N-able’s status page still listed the incident as a major outage under investigation, with no end time. Hosted N-central remained offline in all three regions, and the on-premises N-central rows were marked the same way. N-able said it is seeing scanning tied to the published exploit code, but has no evidence that any customer environment has been successfully exploited. It is still working on a hotfix, with a target of midday November 10, Eastern time, and it continues to recommend that N-central stay offline until that hotfix is available and the server has been upgraded. A check of N-able’s N-central release notes found no new hotfix for this incident; the latest security hotfix listed there is still 2026.4 HF1, dated November 2, which addresses a separate issue.

What to do

  1. Ask your provider. If an MSP or IT firm runs your computers, ask whether they use N-able N-central, hosted or on-premises, and write down the answer.
  2. Upgrade before turning it back on. An on-premises server should be upgraded to N-central 2026.4 Hotfix 2 (build 2026.4.1.26) before it comes back online; N-able upgrades hosted servers itself. Then upgrade Agents first and Probes second, in both hosted and on-premises setups, as the release notes direct.
  3. Check logins and new admin accounts since November 8. Ask your provider to review login activity and any new administrator accounts from November 8 onward, and to look for unexpected remote sessions or new scripts, before they turn N-central back on. Huntress recommends that review because earlier N-central incidents saw attackers create admin accounts and push tools into client networks.
  4. Watch N-able’s status page for the all-clear. Hosted N-central comes back when N-able says so. The official page is uptime.n-able.com.

When this piece first ran, no CVE identifiers had been assigned, according to SecurityWeek. N-able’s Hotfix 2 release notes now list seven, including CVE-2026-125882 (code execution through a file repository upload path traversal) and CVE-2026-125878 (OGNL injection). The flaws were not on CISA’s Known Exploited Vulnerabilities catalog as of feed version 2026.11.09. That does not change the advice. Follow N-able’s current direction rather than waiting for a catalog entry.
